# DESIGN 1.1 — Отметки выполнения

Дизайн-документ подволны 1.1: система отметок статусов для итераций напоминания.

**Статус:** утверждён
**Дата:** 22.09.2026
**Авторы:** Egor-Che (продуктовые решения), ассистент (технические решения)

---

## Цель

Дать пользователю возможность отмечать **каждую отдельную итерацию** повторяющегося
напоминания как «Выполнено», «Пропустить» или «Пропущено». Отметка доступна
из уведомления (для текущей итерации) и с отдельного экрана «Отметить» (для любых
итераций — прошлых и будущих).

---

## Терминология

| Термин | Значение |
|---|---|
| **Итерация** | Одно конкретное срабатывание напоминания в конкретную дату |
| **Выполнено** | Пользователь отметил, что действие выполнено |
| **Пропустить** | Пользователь осознанно пропускает итерацию (может быть заранее) |
| **Пропущено** | Система автоматически отметила прошедшую итерацию без реакции пользователя |
| **Snapshot** | Снимок статусов итераций на момент открытия экрана «Отметить» |

---

## Модель статусов

### Три состояния

| Статус | Источник | Цвет в UI | Иконка |
|---|---|---|---|
| **COMPLETED** | Пользователь | 🟢 Зелёный (насыщенный) | ✅ |
| **SKIPPED (USER)** | Пользователь | 🟡 Жёлтый (насыщенный) | ⏭️ |
| **SKIPPED (SYSTEM)** | Система | 🔴 Красный (насыщенный) | ❌ |
| **PENDING** (нет отметки) | — | ⚪ Серый | пустая иконка |

### Правила

1. **Взаимоисключение.** На одной итерации может быть только один статус.
   Нельзя поставить COMPLETED и SKIPPED одновременно.

2. **Отмена второго тапом.** Второй тап по **той же иконке** снимает статус:
   - COMPLETED → PENDING
   - SKIPPED (USER) → PENDING
   - SKIPPED (SYSTEM) → **не снимается** (автоматическая отметка)

3. **Замена.** Тап по **другой иконке** заменяет статус:
   - PENDING → COMPLETED / SKIPPED (USER)
   - COMPLETED → SKIPPED (USER)
   - SKIPPED (USER) → COMPLETED
   - SKIPPED (SYSTEM) → COMPLETED (заменяется) или → SKIPPED (USER) (перезаписывается пользовательским)

4. **Автопропуск.** Через **3 часа после полуночи даты срабатывания**, если статус
   всё ещё PENDING, система ставит SKIPPED (SYSTEM). Проверка через WorkManager
   раз в 3 часа.

5. **Массовые действия** (см. ниже) не трогают то, что отмечено пользователем
   вручную (USER). Трогают только PENDING и SYSTEM.

## Модель данных

### Новая таблица `iterations`

```
id              — PK, autoGenerate
reminderId      — FK на Reminder (index)
dateMillis      — полночь конкретной итерации
status          — PENDING / COMPLETED / SKIPPED
statusSource    — USER / SYSTEM (null если PENDING)
statusChangedAt — когда был поставлен статус (null если PENDING)
firedAt         — когда реально сработало уведомление (для будущей истории)
```

**Уникальный индекс:** `(reminderId, dateMillis)`.

### Принцип создания записей

Записи создаются в БД **только когда это нужно**:

- Пользователь поставил отметку → создаётся запись.
- Итерация сработала (firedAt) → создаётся/обновляется запись.
- Система поставила автопропуск → создаётся запись.

Для всех остальных итераций записей в БД **нет**. Они генерируются «на лету»
при отображении экрана «Отметить» — по расписанию напоминания.

**Плюс:** таблица не пухнет от бессрочных ежедневных напоминаний.
**Минус:** при отображении нужно мёржить «сгенерированные» итерации с БД.

### Миграция БД

Версия 3 → 4:
- Создаётся таблица `iterations`.
- Существующие напоминания не трогаются.

## Экран «Отметить»

### Точка входа

- Кнопка **«Отметить»** на карточке напоминания в списке.
- Кнопка **«Выполнено»** в уведомлении — ставит COMPLETED для текущей итерации
  и открывает этот же экран (для последующих правок).

### Структура экрана

```
┌──────────────────────────────────────────┐
│ ←  Отметки: Приём лекарств               │  ← топбар
├──────────────────────────────────────────┤
│ [Выполнить всё прошедшее]                │  ← шапка с массовыми действиями
│ [Пропустить всё будущее]                 │
│  Показать только с отметками  [тумблер]  │
├──────────────────────────────────────────┤
│  21.09.2026, вс  14:30  ✅ ⏭️             │  ← строки итераций
│  22.09.2026, пн  14:30  ✅ ⏭️             │
│  23.09.2026, вт  14:30  ✅ ⏭️  ← выделена │
│  24.09.2026, ср  14:30  ✅ ⏭️             │
│  25.09.2026, чт  14:30  ✅ ⏭️             │
│  ...                                      │
├──────────────────────────────────────────┤
│ [Отменить все изменения сессии]          │  ← футер
└──────────────────────────────────────────┘
```

### Поведение

- **Стартовая позиция:** список сразу отображает ближайшую итерацию,
  момент срабатывания которой ещё не наступил (с учётом времени напоминания,
  не только даты). Если все итерации в прошлом — фокусируется на последней.
  Начальный скролл выполняется программно после загрузки данных.
  При возврате на экран позиция не сбрасывается.
- **Скролл:** вверх — прошлое, вниз — будущее.
- **Ограничение:** ±3 года от текущей даты.
- **Окно загрузки:** ±60 дней изначально, дальше подгрузка по 20 итераций.
- **Учёт границ:** итерации генерируются только между `startDate` и `endDate`.
- **Фон карточки:** цвет напоминания (пастельный тон).

### Строка итерации

- Дата и день недели.
- Время срабатывания.
- Две иконки статуса: ✅ и ⏭️.
- Активная иконка — насыщенный цвет источника.
- Неактивная иконка — серая пустая.
- Тап по иконке — см. правила выше.

### Массовые действия

| Кнопка | Что делает |
|---|---|
| **«Выполнить всё прошедшее»** | Ставит COMPLETED для всех итераций от `startDate` до сегодня, у которых статус PENDING или SKIPPED (SYSTEM). USER-статусы не трогает. Диалог подтверждения. |
| **«Пропустить всё будущее»** | Ставит SKIPPED (USER) для всех итераций от сегодня до min(`endDate`, сегодня+1 год), у которых статус PENDING или SKIPPED (SYSTEM). USER-статусы не трогает. Диалог подтверждения. |
| **«Отменить все изменения сессии»** | Восстанавливает snapshot, снятый при входе на экран. Все изменения текущей сессии откатываются. Активна только если были изменения. |

### Диалоги подтверждения

**«Выполнить всё прошедшее»:**
```
Отметить все прошедшие итерации как выполненные?

Будет отмечено: N итераций
Диапазон: с 01.09.2026 по 22.09.2026

[Отмена] [Отметить]
```

**«Пропустить всё будущее»:**
```
Отметить все будущие итерации как пропущенные?

Будет отмечено: N итераций
Диапазон: с 23.09.2026 по 22.09.2027

[Отмена] [Пропустить]
```

**«Отменить все изменения сессии»:**
```
Отменить все изменения, сделанные за эту сессию?

Изменено итераций: N

[Отмена] [Отменить изменения]
```

## Карточка напоминания в списке

### Новая структура

```
┌────────────────────────────────────────────┐
│ 💊 Приём лекарств                          │
│ 3 дн. подряд, потом 5 дн. пауза            │
│ ─────────────────────────────────────────  │
│ ⬆️ 21.09, вс 14:30     ✅ Выполнено         │
│ ▶️ 22.09, пн 14:30     ⏳ Ожидает           │
│ ⏭️ 23.09, вт 14:30     —                    │
│ ─────────────────────────────────────────  │
│ [Отметить]                       [🔔] [🔘]│
└────────────────────────────────────────────┘
```

### Отображаемые итерации

1. **Прошлая** — последняя итерация до сегодня включительно.
2. **Ближайшая** — первая итерация сегодня или в будущем.
3. **Следующая** — итерация после ближайшей.

Для каждой:
- Дата и время.
- Статус (если есть): «✅ Выполнено», «⏭️ Пропущено», «❌ Пропущено (авто)».
- Если статуса нет — пусто или «—».

### Кнопка «Отметить»

Расположена слева под блоком итераций. Открывает экран «Отметить».

## Уведомления

### Новая кнопка «Выполнено»

В уведомлении теперь **три** действия:

```
[Выполнено]  [Отложить 5 мин]  [Отложить 10 мин]
```

- «Выполнено» → ставит COMPLETED для текущей итерации, закрывает уведомление.
- «Отложить 5 мин» / «Отложить 10 мин» — как раньше.

---

## Фоновая простановка автопропуска

### WorkManager

- Периодическая задача раз в 3 часа.
- Проходит по всем активным напоминаниям.
- Для каждой прошедшей итерации, где прошло 3 часа после полуночи и статус PENDING →
  ставит SKIPPED (SYSTEM).
- Не трогает COMPLETED и SKIPPED (USER).

### Дополнительно

- Также проверка при запуске приложения (на случай, если WorkManager
  не сработал из-за ограничений системы).

## Приложения

### Примеры статусов в разных ситуациях

**Ситуация 1. Пользователь принял таблетку вовремя.**
- Итерация сегодня 14:30 → в 14:30 сработало → пользователь нажал «Выполнено».
- Через 3 часа (после полуночи) система НЕ ставит автопропуск — статус уже COMPLETED.

**Ситуация 2. Пользователь принял таблетку, но не нажал кнопку.**
- Итерация сегодня 14:30 → сработало → пользователь не отреагировал.
- Через 3 часа после полуночи (в 03:00 следующих суток) система ставит SKIPPED (SYSTEM).
- Утром пользователь открывает приложение, видит «❌ Пропущено», тапает на ✅ → статус меняется на COMPLETED.

**Ситуация 3. Пользователь забыл принять, но вспомнил через 2 дня.**
- Итерация 2 дня назад 14:30 → SKIPPED (SYSTEM).
- Пользователь открывает экран «Отметить», скроллит вверх, находит итерацию, тапает ✅.
- Статус меняется на COMPLETED.

**Ситуация 4. Пользователь уехал в отпуск, напоминание было ежедневным.**
- 10 прошедших итераций → SKIPPED (SYSTEM) автоматически.
- Пользователь возвращается, открывает экран «Отметить», жмёт «Выполнить всё прошедшее».
- Все 10 итераций получают COMPLETED.
- При этом если какие-то из них уже были отмечены вручную — они не трогаются.

**Ситуация 5. Пользователь заранее знает, что пропустит.**
- Будущая итерация завтра 09:00 → пользователь тапает ⏭️ → SKIPPED (USER).
- Завтра в 09:00 уведомление НЕ срабатывает.
- Через 3 часа после полуночи система НЕ ставит SKIPPED — статус уже USER-ский.

**Ситуация 6. Пользователь передумал отменять.**
- Поставил SKIPPED (USER) на завтра 09:00.
- Через час решил, что всё-таки примет лекарство, тапает ⏭️ снова.
- Статус снимается → PENDING.
- Завтра в 09:00 сработает уведомление.

**Ситуация 7. Пользователь случайно нажал «Выполнено» в уведомлении.**
- Уведомление закрылось, статус COMPLETED.
- Открывает экран «Отметить», находит итерацию сегодня, тапает ✅ снова.
- Статус снимается → PENDING.
- Но уведомление уже было — повторно не сработает. Это известное ограничение.
  В бэклог: возможность «отложить повторно» после отмены.
