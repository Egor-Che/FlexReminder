# DESIGN 1.4 — Архив напоминаний и история итераций

Дизайн-документ подволны 1.4: архив напоминаний с автоперемещением
по endDate, экран истории напоминания с подробной хронологией итераций.

**Статус:** утверждён
**Дата:** 24.09.2026
**Авторы:** Egor-Che (продуктовые решения), ассистент (технические решения)

---

## Цель

Дать пользователю «полку прошлого» — отдельный экран с напоминаниями,
которые уже закончились (наступила endDate), и подробной историей
их срабатываний. История нужна и для ностальгии («вот как я пил
таблетки три года»), и для практики («создать новое напоминание
по образцу старого»).

---

## Терминология

| Термин | Значение |
|---|---|
| **Архив** | Список напоминаний с истёкшим endDate |
| **История** | Детальный экран архивного напоминания |
| **Перенос** | То, что раньше называлось snooze (отложить уведомление). Слово «Snooze» не используется в UI. |
| **Итерация** | Одно запланированное срабатывание напоминания в конкретную дату |

---

## Модель данных

### Поле `archivedAt: Long?` в Reminder

- `null` — активное напоминание.
- не `null` — время архивации (мс).

### Поле `snoozeHistory: String` в Iteration

Формат: `"timestamp1:minutes1,timestamp2:minutes2,..."`

- Максимум 5 записей (по лимиту переносов).
- Пустая строка — не было переносов.
- Парсится в список пар `(timestamp, minutes)`.

**Пример:** `"1727000000000:30,1727001800000:60"` — два переноса: первый на 30 мин, второй на 1 час.

### Миграция БД: 8 → 9

```sql
ALTER TABLE reminders ADD COLUMN archivedAt INTEGER;
ALTER TABLE iterations ADD COLUMN snoozeHistory TEXT NOT NULL DEFAULT '';
```

## Автоперемещение в архив

### Условие архивации

```sql
UPDATE reminders
SET archivedAt = <now>
WHERE endDate IS NOT NULL
  AND endDate < <today midnight>
  AND archivedAt IS NULL
```

Независимо от `enabled`. Если напоминание перестало быть активным
по дате — оно уходит в архив.

### Когда запускается

1. **При старте приложения** (`MainActivity.onCreate`, в фоновой корутине).
2. **При перезагрузке устройства** (`BootReceiver`).

Иных триггеров нет. Этого достаточно.

### Что происходит с итерациями

Перед архивацией — **финальный проход по PENDING-итерациям**:

```sql
UPDATE iterations
SET status = 'SKIPPED',
    statusSource = 'SYSTEM',
    statusChangedAt = <now>
WHERE reminderId = <id>
  AND status = 'PENDING'
```

После этого у архивного напоминания все итерации имеют финальный
статус (COMPLETED / SKIPPED), pending не остаётся.

## Экран «Архив напоминаний»

### Точка входа

Иконка `Archive` в топбаре главного экрана, **слева от шестерёнки**.

### Заголовок

**«Архив напоминаний»** — фиксированный, в топбаре.

### Список

Карточки — компактные, **без свитчей, без иконок звука, без кнопки «Отметить»**.

Фон карточки — **серая зебра** (чётная позиция светлее, нечётная темнее),
независимо от текущей темы приложения. Цвет напоминания не используется.

**Содержимое карточки:**

```
┌──────────────────────────────────────────┐
│ Приём лекарств                           │
│ 10 лет                                   │
│ Раз в 22 дн.                             │
│ С 01.09.2021 по 18.05.2024               │
└──────────────────────────────────────────┘
```

Клик по карточке → открывается экран «История напоминания» (роут `archive/{id}`).

### Сортировка

По `archivedAt` в порядке **убывания** (недавно заархивированные — вверху).

### Пустое состояние

```
Архив пуст

Здесь будут напоминания, которые закончились —
после наступления даты окончания.
```

## Экран «История напоминания»

### Точка входа

Клик по карточке в архиве.

### Топбар

- Заголовок: **«История напоминания»** — фиксированный.
- Иконка справа: `Delete` (мусорное ведро).
- Кнопка «Назад» слева.

### Тело экрана

```
┌──────────────────────────────────────────┐
│ Приём лекарств                           │  ← название, заголовок
│ 10 лет                                   │  ← заметка
│                                          │
│ Раз в 22 дн.                             │  ← тип расписания
│ Период: 01.09.2021 — 18.05.2024          │
│                                          │
│ 15:10     Со звуком                      │  ← время + звук
│                                          │
│ [календарь с подсветкой активных дней]   │
│                                          │
│ [Создать по примеру]                     │  ← акцентная кнопка
│ [Удалить]                                │  ← серая кнопка
└──────────────────────────────────────────┘
```

**Что показываем:**
- Название напоминания — как `headlineSmall`.
- Заметка — если не пустая.
- Тип расписания: «Раз в N дн.» / «N дн. подряд, потом M дн. пауза» / «Конкретные даты: N шт.»
- Период: `с startDate по endDate`.
- Время: `HH:mm`.
- Звук: «Со звуком» / «Без звука». Мелодию **не показываем** (URI может быть невалиден, имя недоступно).

**Что НЕ показываем:**
- Цвет напоминания.
- Мелодию.
- Статусы «Включено / Выключено».

### Календарь

`ReminderCalendar` в режиме `readOnly = true`, тема — **Монохром**
(серая гамма, приглушённая подсветка).

Тап на подсвеченный день → открывается **модалка итерации**.

### Кнопки внизу

1. **«Создать по примеру»** — акцентная (в цвете темы).
2. **«Удалить»** — серая, без выделения цветом.

Обе — во всю ширину экрана, друг под другом.

## Модалка итерации

Открывается при тапе на подсвеченный день в календаре.

### Позиционирование

- По центру экрана.
- Если содержимое не помещается — вертикальный скролл внутри модалки.
- Закрывается тапом по любому месту модалки (вне контента) или системной кнопкой «Назад».

### Содержимое (итерация с полной историей)

```
┌─────────────────────────────────────┐
│ 21.09.2021, вторник                 │
├─────────────────────────────────────┤
│ Назначено:  14:30                   │
│ Сработало:  14:30                   │
│                                     │
│ Переносы:                           │
│  • 14:35 → на 30 мин                │
│  • 15:10 → на 1 час                 │
│                                     │
│ Статус:     ✅ Выполнено            │
│ Время:      16:20 21.09.2021        │
└─────────────────────────────────────┘
```

### Содержимое (итерация без записей в БД)

```
┌─────────────────────────────────────┐
│ 21.09.2021, вторник                 │
├─────────────────────────────────────┤
│ Назначено:  14:30                   │
│                                     │
│ Действий не зафиксировано.          │
│ Возможно, устройство было отключено.│
└─────────────────────────────────────┘
```

### Правила

- Блок **«Переносы:»** — показывается только если `snoozeHistory` не пустой.
  Если переносов не было, блок схлопывается.
- Строка **«Сработало:»** — показывается, если есть `firedAt`.
- Строка **«Статус:»** — показывается, если статус отличается от PENDING.
- Все временные метки — в формате `HH:mm DD.MM.YYYY`, чтобы было видно,
  если перенос или статус ушёл на следующую дату.

## Словарь замен: Snooze → Перенос

Слово «Snooze» **удаляется из всех пользовательских текстов**.
В коде остаётся как есть.

| Где | Было | Стало |
|---|---|---|
| Уведомление | «Отложить 30 мин» | «Перенести 30 мин» |
| Уведомление | «Отложить 1 час» | «Перенести 1 час» |
| Настройки: секция | «Snooze (отложить напоминание)» | «Перенос напоминаний» |
| Настройки: строки | «Короткий интервал» / «Длинный интервал» | «Короткий перенос» / «Длинный перенос» |
| Настройки: диалог | «Короткий интервал» / «Длинный интервал» | «Короткий перенос» / «Длинный перенос» |
| Модалка итерации | (новое) | «Переносы:» |

**В коде:** классы, поля, методы, константы — остаются с `snooze`.
Меняются только строковые ресурсы и подписи в UI.

## Создание по примеру

### Точка входа

Кнопка **«Создать по примеру»** внизу экрана Истории.

### Что копируется

| Поле | Что делаем |
|---|---|
| `title` | Копируем как есть. Пользователь потом сам отредактирует. |
| `notes` | Копируем как есть. |
| `mode` | Копируем как есть. |
| `daysOn`, `daysOff` | Копируем как есть. |
| `customDates` | **Сдвигаем** относительно нового startDate (см. ниже). |
| `hour`, `minute` | Копируем как есть. |
| `colorIndex` | Копируем как есть. |
| `silent` | Копируем как есть. |
| `soundUri` | **Обнуляем** (файл мог быть удалён, трек мог быть недоступен). |
| `enabled` | Устанавливаем `true` — пользователь только что создал напоминание. |
| `archivedAt` | `null`. |

### Что НЕ копируется

- `id` — новое.
- `startDate` — устанавливаем текущую дату.
- `endDate` — вычисляем по формуле.

### Формула дат

```
oldDuration = oldEndDate - oldStartDate
newStartDate = сегодня (полночь)
newEndDate = newStartDate + oldDuration
```

**Пример:** старое напоминание работало с 01.09.2021 по 18.05.2024
(≈ 990 дней). Новое будет работать с сегодня по сегодня + 990 дней.

### Обработка customDates

Если старое напоминание было в режиме `CUSTOM_DATES`, сохраняем
**относительные позиции** дат относительно старого startDate.

```
shift = newStartDate - oldStartDate
newDates = oldDates.map { it + shift }.toSet()
```

**Пример:**
- Старые даты: 1 сентября, 15 сентября, 30 сентября 2021.
- Старый startDate: 1 сентября 2021.
- Сегодня: 24 сентября 2026.
- shift = (24.09.2026 - 01.09.2021) = 5 лет + 23 дня.
- Новые даты: те же позиции в новом окне.

Это позволяет сохранить ритм: «в первый день, через 2 недели, в конце».

### Что происходит после создания

1. Открывается **редактор** нового напоминания с уже заполненными полями.
2. Пользователь может что-то поправить перед сохранением.
3. Если он сохраняет — напоминание попадает в активный список.
4. Если отменяет — ничего не создаётся.

### Что показываем в UI

При тапе кнопки — никаких диалогов. Сразу переход в редактор с
предзаполненными полями.

## Удаление архивного напоминания

### Точки входа

1. **Иконка `Delete`** в топбаре экрана Истории.
2. **Кнопка «Удалить»** внизу экрана Истории.

Обе ведут к одному действию.

### Диалог подтверждения

```
Удалить архивное напоминание?

Всё, включая историю срабатываний, будет удалено безвозвратно.

[Отмена]   [Удалить]
```

### Что удаляется

Через существующий метод `ReminderViewModel.deleteById(id)`:

1. Отменяются будильники (уже неактивны, но на всякий случай).
2. Отменяются активные snooze (тоже неактивны).
3. Удаляются все итерации напоминания.
4. Удаляется само напоминание.

Каскадное удаление уже реализовано. Ничего нового не пишем.

### После удаления

Возврат на экран «Архив напоминаний». Карточка исчезает.

## Что НЕ входит в 1.4

- **Фиксация цвета при архивации** — решено, что архив всегда серый с зеброй. Поле `archivedColorIndex` не нужно.
- **Мелодия в истории** — не показываем. Причины: URI может быть невалиден, имя трека может быть недоступно.
- **Отдельный экран «История» вне архива** — история открывается только из архива.
- **Восстановление из архива** — нет. Только «Создать по примеру».
- **Экспорт истории** — не в этой подволне.

## План работ

### Этап 1. Модель данных

1. Поле `archivedAt: Long?` в `Reminder`.
2. Поле `snoozeHistory: String` в `Iteration`.
3. Миграция БД 8 → 9.
4. Запись `snoozeHistory` в `SnoozeReceiver.handleSnoozeButton`.

### Этап 2. Автоперемещение

1. Метод в `ReminderDao`: `archiveExpired(now: Long, todayMidnight: Long)`.
2. Метод в `IterationDao`: `markPendingAsSkippedForReminder(reminderId, now)`.
3. Вызов из `MainActivity.onCreate`.
4. Вызов из `BootReceiver`.

### Этап 3. Экран «Архив напоминаний»

1. Иконка `Archive` в топбаре главного экрана.
2. Роут `archive`.
3. `ArchiveScreen.kt` — список компактных карточек.
4. `ArchiveViewModel.kt` — стейт архивных напоминаний.

### Этап 4. Экран «История напоминания»

1. Роут `archive/{id}`.
2. `ReminderHistoryScreen.kt` — топбар, тело, календарь, кнопки.
3. `ReminderHistoryViewModel.kt` — загрузка напоминания и итераций.

### Этап 5. Модалка итерации

1. Компонент `IterationDetailsDialog.kt`.
2. Парсер `snoozeHistory`.
3. Форматирование времени и статусов.

### Этап 6. Создание по примеру

1. Логика в `ReminderHistoryViewModel` — построение `Reminder` по образцу.
2. Навигация в редактор с флагом «создать из шаблона».
3. Обработка `customDates` со сдвигом.

### Этап 7. Замена Snooze → Перенос в UI

1. В `Notifications.formatSnoozeLabel` → «Перенести ...».
2. В `SettingsScreen` — секция «Перенос напоминаний», поля «Короткий перенос» / «Длинный перенос».
3. В диалоге редактора snooze — то же.
4. В модалке итерации — «Переносы:».

### Этап 8. Тест-кейсы и проверка

1. Модуль 16 в `TEST_CASES.md`.
2. Проверка на POCO + Mi 8 Lite + Mi A2.

**Оценка:** 3–4 сессии.

## Открытые вопросы

1. **Сколько итераций хранить в `snoozeHistory`?**
   Решено: до 5 (совпадает с лимитом snooze).

2. **Что если `snoozeHistory` повреждён (невалидный формат)?**
   Парсер должен вернуть пустой список. Без падений.

3. **Что если архивных напоминаний очень много (100+)?**
   LazyColumn, пагинация не нужна на этом объёме.

4. **Можно ли считать `snoozeHistory` для активных напоминаний?**
   Да. У нас нет ограничения «только для архива». Открыть модалку
   с историей итерации активного напоминания — фича на будущее,
   но данные уже готовы.
