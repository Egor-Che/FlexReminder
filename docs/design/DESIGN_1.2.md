# DESIGN 1.2 — Звуки уведомлений

Дизайн-документ подволны 1.2: выбор звука уведомления — глобально
и для отдельных напоминаний. Системные звуки, свои файлы, дефолт.

**Статус:** утверждён
**Дата:** 23.09.2026
**Авторы:** Egor-Che (продуктовые решения), ассистент (технические решения)

---

## Цель

Дать пользователю возможность выбрать звук уведомления:
- Глобально для всех напоминаний (в настройках).
- Индивидуально для конкретного напоминания (в редакторе).

Источники звука: системные (звонки / уведомления / будильники) и свои
файлы через SAF.

---

## Развилка по API

`minSdk` поднят с 24 до **28 (Android 9)**. Это означает:
- Каналы уведомлений есть гарантированно.
- Никаких веток `if (SDK_INT < 26)`.
- Единая логика через каналы.

## Терминология

| Термин | Значение |
|---|---|
| **Дефолт** | Системный звук уведомлений (или первый выбранный глобально). |
| **Глобальный звук** | Звук по умолчанию для всех напоминаний (настройка приложения). |
| **Свой звук** | Звук, выбранный для конкретного напоминания (переопределяет глобальный). |
| **Канал** | NotificationChannel — единица, к которой привязан звук на Android 8+. |

## Логика выбора звука при показе уведомления

Порядок приоритетов (сверху вниз):

```
1. Reminder.silent = true
   → канал reminders_silent (без звука)

2. Reminder.soundUri != null
   → канал reminders_custom_<hash(Reminder.soundUri)>

3. Глобальный звук из настроек != null
   → канал reminders_default_<hash(globalSoundUri)>

4. Ничего не выбрано
   → канал reminders_loud (системный дефолт)
```

---

## Схема каналов (хэш-подход)

**Принцип:** один уникальный звук = один канал.

- `reminders_loud` — базовый, с системным дефолтом.
- `reminders_silent` — беззвучный.
- `reminders_custom_<hash>` — для звуков, выбранных для конкретных напоминаний.
- `reminders_default_<hash>` — для глобального звука в настройках.

**Hash** = первые 8 символов `sha1(uri)`. Пример: `a3f5b21c`.

**Свойства схемы:**
- 50 напоминаний с одним звуком → 1 канал.
- 5 напоминаний с разными звуками → 5 каналов.
- Один и тот же звук в глобальном и в напоминании → один канал.

### Реакция на события

**Выбор нового звука для напоминания:**
1. Хэш нового URI → если канала нет, создать.
2. Сохранить `Reminder.soundUri`.
3. Проверить старый канал на использования другими напоминаниями.
   - Никем → удалить.

**Смена глобального звука:**
- **Первый раз** — пересоздать `reminders_loud` с новым звуком.
- **Далее** — создать `reminders_default_<hash>`, старый удалить, если не используется.

**Удаление напоминания:**
- Удалить напоминание.
- Проверить, используется ли его канал где-то ещё.
- Если нет — удалить канал.

**Невалидный URI (файл удалён):**
- При попытке показать уведомление → `try/catch`.
- Сброс `Reminder.soundUri` на null.
- Уведомление показывается через `reminders_loud`.

**Запуск приложения:**
- Раз в сессию пробегать по каналам `reminders_custom_*` и `reminders_default_*`.
- Удалять «сиротские» (не используемые ни одним напоминанием и не равные текущему глобальному).

## UI. Диалог выбора звука

Единый для настроек и редактора.

### Верхняя часть

- Заголовок «Выбрать звук».
- Строка «Выбрано: <название трека>» или «Не выбрано».
- Кнопки **Play** / **Stop** рядом со строкой.

### Табы

Три вкладки для категорий системных звуков:
- **Звонки** (`RingtoneManager.TYPE_RINGTONE`).
- **Уведомления** (`RingtoneManager.TYPE_NOTIFICATION`).
- **Будильники** (`RingtoneManager.TYPE_ALARM`).

В каждой вкладке — список треков этой категории. Активный выделен галочкой.

### Нижняя часть

- Кнопка **«Мой файл»** → SAF (`ACTION_OPEN_DOCUMENT`, тип `audio/*`).
- Кнопка **«По умолчанию»** → сброс на дефолт (при первом использовании
  это `reminders_loud`, потом — выбранный глобальный).

### Поведение

- **Превью:** только по кнопке Play. Никаких автозапусков.
- **Кнопка Play:** играет трек до конца или до нажатия Stop.
- **Кнопка Stop:** останавливает воспроизведение.
- **Закрытие диалога:** останавливает воспроизведение.
- **При выборе трека** — превью не запускается автоматически.

## Логика сохранения звука

### В настройках

1. Пользователь тапает «Звук по умолчанию».
2. Выбирает трек.
3. Сохраняем URI в DataStore.
4. Создаём канал (или переиспользуем существующий).
5. Удаляем старый канал, если он больше никем не используется.

### В редакторе напоминания

1. Пользователь тапает «Звук: <название>».
2. Выбирает трек.
3. Сохраняем URI в `Reminder.soundUri`.
4. **При сохранении напоминания** — создаём канал, удаляем старый, если не нужен.

## Технические решения

### Класс для работы с каналами

Создаём `alarm\NotificationChannels.kt`:
- `getOrCreateChannelForUri(context, uri): String` — возвращает ID канала,
  создаёт его при необходимости.
- `cleanupUnusedChannels(context, activeSoundUris: Set<String>)` — удаляет
  каналы, не используемые ни одним напоминанием и не совпадающие
  с текущим глобальным.
- `computeChannelId(uri: String): String` — hash + префикс.

### Валидация URI

Функция `isUriValid(context, uri): Boolean` — проверяет, что файл доступен.
Используется в `SnoozeReceiver`, `ReminderReceiver` при выборе звука.

### Обновление существующего кода

**Notifications.kt** перерабатывается:
- `ensureChannels` остаётся для базовых (`loud`, `silent`).
- Новый метод `resolveChannelFor(context, reminder, globalUri): String` —
  возвращает ID канала по правилам приоритета.
- `show()` принимает ID канала вместо `silent: Boolean`.

**SnoozeReceiver.kt** и **ReminderReceiver.kt** — используют
`resolveChannelFor` при показе.

## Детали работы с SAF

### Получение доступа к файлу

- Используем `ACTION_OPEN_DOCUMENT` (не `ACTION_GET_CONTENT`), потому что только
  он даёт persistable URI.
- MIME-тип: `audio/*`.
- После выбора файла вызываем
  `contentResolver.takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)`.
- Без этого доступ потеряется после перезапуска приложения.

### Валидация URI

Функция `isUriValid(context, uri: String): Boolean`:

```kotlin
fun isUriValid(context: Context, uri: String): Boolean {
    return try {
        context.contentResolver.openInputStream(Uri.parse(uri))?.use { true } ?: false
    } catch (e: Exception) {
        false
    }
}
```

Используется:
- При открытии диалога выбора звука.
- При показе уведомления (в `ReminderReceiver` / `SnoozeReceiver`).
- При запуске приложения (проверка всех напоминаний с `soundUri != null`).

### Поведение при невалидном URI

**При показе уведомления:**
- Пытаемся получить канал.
- Если URI невалиден → `try/catch`, фолбэк на `reminders_loud`.
- Параллельно (в фоне) обновляем `Reminder.soundUri = null` в БД.
- При следующем показе напоминание уже использует дефолт.

**При открытии редактора/настроек:**
- Если сохранённый URI невалиден → отображаем «Звук не найден».
- В редакторе кнопка сброса активна — можно откатить.

## Жизненный цикл каналов

### Создание канала

Канал создаётся лениво, только когда он реально нужен:

1. **При сохранении напоминания** с `soundUri != null`:
   - Вычисляем hash → `reminders_custom_<hash>`.
   - Если канала нет — создаём.
   - Если канал есть — ничего не делаем.

2. **При сохранении глобального звука** (первый раз):
   - Пересоздаём `reminders_loud` с новым звуком.

3. **При сохранении глобального звука** (повторно):
   - Создаём `reminders_default_<hash>`, если его нет.
   - Старый `reminders_default_<oldHash>` удаляем, если он нигде не используется.

### Удаление канала

Канал удаляется, если выполнены **все** условия:
- Ни одно напоминание не использует этот `soundUri`.
- Глобальный звук не совпадает с этим URI.

Проверка вызывается:
- При удалении напоминания.
- При смене звука напоминания.
- При смене глобального звука.
- При запуске приложения (общий cleanup).

### Что делать, если один и тот же звук используется в нескольких местах

Один канал на всех. Никакого дублирования. Канал переживёт, пока есть
хотя бы один потребитель.

## Граничные случаи

### Пользователь выбирает тот же звук, что был

- Ничего не меняется.
- Канал уже есть.
- Никаких пересозданий.

### Пользователь выбирает звук, который уже используется другим напоминанием

- Канал переиспользуется.
- Оба напоминания ссылаются на один канал.
- Удаление одного напоминания не сносит канал.

### Пользователь сбрасывает звук напоминания на дефолт

- `Reminder.soundUri = null`.
- Канал проверяется на использование другими напоминаниями.
- Если никем — удаляется.

### Миграция БД

После миграции 6 → 7:
- У всех напоминаний `soundUri = null`.
- Все они используют `reminders_loud` (глобальный дефолт).
- Никаких каналов создавать не нужно.

### Пустой список системных звуков

На эмуляторах или специфичных устройствах может не быть рингтонов
в одной из категорий. В этом случае вкладка показывает «Звуки не найдены».

## Как выглядит выбор «своего файла»

1. Пользователь в диалоге нажимает «Мой файл».
2. Открывается системный SAF-пикер с фильтром `audio/*`.
3. Пользователь выбирает файл.
4. Получаем URI, сохраняем persistable permission.
5. Возвращаемся в диалог, показываем «Выбрано: <имя файла>».
6. При сохранении — записываем `Reminder.soundUri` или глобальный.

**Примечание:** SAF-пикер — это системный экран. Он открывается через
`rememberLauncherForActivityResult(ActivityResultContracts.OpenDocument())`.
